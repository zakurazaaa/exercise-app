# เมื่อของมาถึง → ทำต่อยังไง (FitPedia Rep Counter)

คู่มือเช็กลิสต์สำหรับเซนเซอร์นับ rep อัตโนมัติ บอร์ด **Seeed XIAO nRF52840 Sense**
(ทุกขั้นตอน/ตัวเลขในนี้ตรวจสอบกับ Seeed wiki, ST datasheet, MDN, caniuse และ source ของ core แล้ว)

---

## 0) เช็กของก่อนเริ่ม
- [ ] บอร์ด **Seeed XIAO nRF52840 Sense** (ต้องรุ่น "Sense" — มี IMU ในตัว)
- [ ] สาย **USB-C** (แบบส่งข้อมูลได้ ไม่ใช่สายชาร์จอย่างเดียว)
- [ ] แบตลิเธียม 3.7V ตัวเล็ก + สวิตช์ (ถ้าจะใช้ไร้สายจริง) — ตอนจูนใช้ไฟจาก USB ได้
- [ ] กล่อง/สายรัด/แม่เหล็ก สำหรับยึดเข้าบาร์
- [ ] มือถือ **Android + Chrome** (สำหรับทดสอบเชื่อมแอป) — iPhone ดูขั้นที่ 4

---

## 1) ติดตั้ง Arduino IDE + บอร์ด (ครั้งเดียว)
1. โหลด **Arduino IDE 2.x** (ฟรี จาก arduino.cc)
2. เปิด **Arduino IDE → Preferences** → ช่อง *Additional Boards Manager URLs* วาง:
   ```
   https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json
   ```
3. **Tools → Board → Boards Manager** → ค้น `seeed nrf52` → ติดตั้ง **"Seeed nRF52 Boards"**
   > ⚠️ เลือกตัวนี้ (ไม่ใช่ "mbed-enabled") เพราะเราใช้ **Bluefruit BLE** — ทำงานได้เฉพาะ core นี้
4. **Tools → Board** → เลือก **"Seeed XIAO nRF52840 Sense"** (อย่าเลือกตัวที่ไม่มีคำว่า Sense)
5. **Library Manager** (ไอคอนหนังสือ) → ค้น `LSM6DS3` → ติดตั้ง **"Seeed Arduino LSM6DS3"**

> 💡 firmware มี `#include <Adafruit_TinyUSB.h>` อยู่แล้ว — จำเป็นบน core นี้ ไม่งั้น Serial คอมไพล์ไม่ผ่าน

---

## 2) Flash firmware ลงบอร์ด
1. เสียบบอร์ดด้วย USB-C
2. เปิดไฟล์ [`rep-counter/rep-counter.ino`](rep-counter.ino)
3. **Tools → Port** → เลือกพอร์ต `/dev/cu.usbmodemXXXX` (บน Mac ไม่ต้องลงไดรเวอร์)
4. กดปุ่ม **Upload** (ลูกศร →) รอ `Done uploading`
5. บอร์ดจะรีเซ็ตแล้วรันเอง — ไฟ LED กะพริบ = ทำงาน

**ถ้า upload ไม่ผ่าน / หาพอร์ตไม่เจอ:**
- กดปุ่ม **RESET** (อยู่ซ้ายของช่อง USB-C) **เร็วๆ 2 ครั้ง** → เข้าโหมด bootloader
- จะมีไดรฟ์ชื่อ **`XIAO-SENSE`** โผล่บน Finder (ลากไฟล์ `.uf2` วางลงไปก็ flash ได้)
- **Tools → Port เปลี่ยนตอนอยู่โหมด bootloader** → เลือกพอร์ตใหม่แล้ว Upload อีกครั้ง

---

## 3) จูนการนับ rep (ผ่าน Serial Monitor)
1. เปิด **Tools → Serial Monitor** (Cmd+Shift+M) → ตั้ง baud **115200** (มุมขวาล่าง)
2. ควรเห็น: `IMU OK` และ `BLE advertising: 'FitPedia-RepCounter'`
3. โยกบอร์ดขึ้น-ลงเลียนแบบยกเวท → ทุก rep จะพิมพ์:
   ```
   REP 1 | v=850mm/s | t=1200ms
   ```
4. **ปรับค่าใน `rep-counter.ino` (บรรทัด ~44) ให้ตรงกับท่าจริง:**

   | ค่า | ความหมาย | ปรับเมื่อ |
   |---|---|---|
   | `HIGH_G` (0.30) | แรงที่ถือว่า "เริ่มขยับ" | นับเกิน→เพิ่ม / ไม่นับ→ลด |
   | `LOW_G` (0.12) | แรงที่ถือว่า "หยุด" | ต้องต่ำกว่า HIGH_G เสมอ (กันเด้ง) |
   | `MIN_REP_MS` (800) | เวลาต่ำสุดต่อ rep (กันนับซ้ำ) | เล่นเร็ว→ลด / เด้งซ้ำ→เพิ่ม |
   | `REST_MS` (4000) | นิ่งกี่ ms = จบเซ็ต | ตามจังหวะพักจริง |

   > วิธีจูน: ยก 10 ครั้งจริง แล้วดูว่านับได้ 10 ไหม ปรับทีละค่าจนตรง ลองทั้งเล่นเร็ว/ช้า/หยุดกลางคัน

---

## 4) เชื่อมกับแอป FitPedia
เปิดท่าที่ไม่ใช่ cardio → กล่อง **"บันทึกการเล่น"** จะมีปุ่ม **🔗 เชื่อมเซนเซอร์นับ rep**

**บน Android (Chrome) — ใช้ได้เต็ม:**
1. เปิด Bluetooth ที่มือถือ + เปิด https://zakurazaaa.github.io/exercise-app/ ใน Chrome
2. กดปุ่ม 🔗 → เลือก **"FitPedia-RepCounter"** จากรายการ → เชื่อม
3. ยกเวท → ช่อง "ครั้ง (reps)" เด้งอัตโนมัติ → กด "บันทึกเซ็ต" (เซนเซอร์รีเซ็ตให้เอง)
   > 🔧 ถ้ากดแล้วไม่เจออุปกรณ์: **เปิด Location** ของมือถือด้วย (Android บางรุ่นบังคับให้เปิดเพื่อสแกน BLE)

**บน iPhone — Safari ใช้ไม่ได้ (Apple บล็อก Web Bluetooth ทุกเบราว์เซอร์):**
- โหลดแอป **"Bluefy - Web BLE Browser"** จาก App Store (**ฟรี**)
- เปิดลิงก์แอปใน Bluefy แทน Safari → ปุ่ม 🔗 จะใช้งานได้
- (ทางเลือกเสียเงิน ~$1.99 คือ "WebBLE" แต่รองรับแค่บางส่วน — แนะนำ Bluefy)

---

## 5) ยึดเซนเซอร์เข้าบาร์ (สำคัญต่อความแม่น)
จากงานวิจัย VBT: **ยึดที่ปลอกบาร์ (collar/sleeve) ด้านในถัดจากแผ่นน้ำหนัก** ดีที่สุด
- บาร์เป็นแท่งแข็ง → ทุกจุดความเร็วเท่ากัน และไม่มี noise จากข้อมือ/แขน
- **ข้อมือ = แม่นน้อยกว่า** (มีการหมุนแขนปน) — ใช้ได้แต่ค่าเพี้ยนขึ้น
- ตำแหน่งเป๊ะๆ บนปลอกบาร์ไม่สำคัญมาก (ต่างกันแค่ ~3-5%) → เลือกที่ยึด**แน่น**และปลอดภัยเป็นหลัก
- ยึดให้แน่นสนิท (แม่เหล็ก/สายรัด) อย่าให้ขยับเอง
- ถ้ากล่องหนัก แนะนำถ่วงน้ำหนักปลายบาร์อีกข้างให้สมดุล

**ท่าที่เหมาะ:** บาร์เบล/ดัมเบลล์คอมพาวด์ (เบนช์, สควอต, เดดลิฟต์, hip thrust), เครื่องราง 1 แนว
**ท่าที่ไม่เหมาะ:** ท่าเกร็งค้าง (isometric), ท่าช้ามากๆ, ท่าเคลื่อนไหวหลายทิศ

---

## 6) ของแถม (เปิดใช้ทีหลังได้)
**velocity/tempo (VBT):** firmware ส่งค่าออกทาง BLE characteristic `…0004` อยู่แล้ว
(6 ไบต์: reps | peakVel มม./วิ | tempo ms) — ค่อยต่อฝั่งแอปให้โชว์ทีหลัง
> ⚠️ เป็นค่า **ประมาณ** (drift) เหมาะเทียบ rep ต่อ rep ในเซ็ตเดียว เช่น "ช้าลง = ล้า → หยุด"
> ไม่ใช่ค่าจริงเป๊ะ อยากแม่นต้องเทียบกับ ROM จริง (ระยะยกที่วัดด้วยตลับเมตร)

**deep sleep (ประหยัดแบตสุด):** ในไฟล์ตั้ง `DEEP_SLEEP_ENABLE = true` (บรรทัด ~46)
- นิ่งครบ 5 นาที → หลับลึก, **ปลุกด้วยการขยับ** (ตั้งขา INT1 = P0.11/ขา18 ให้แล้ว)
- ⚠️ ปลุกจาก System OFF = บอร์ด**รีเซ็ต** → BLE หลุด ต้องกดเชื่อมใหม่ในแอป (เป็นเรื่องปกติของโหมดนี้)
- ตอนเปิดตลอด (ไม่ deep sleep) ก็ประหยัดอยู่แล้วจาก adaptive sampling (พัก=อ่านช้าลง)

## 🛠 แก้ปัญหาที่เจอบ่อย
| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| คอมไพล์ error เรื่อง `Serial` | ใช้ core ผิด — ต้องเป็น "Seeed nRF52 Boards" (มี `Adafruit_TinyUSB.h` แล้ว) |
| `IMU init FAILED` | ปกติแก้ให้แล้ว (เปิดไฟ IMU ขา 15 ก่อน begin) — ถ้ายังเจอ ลองกด RESET |
| upload ไม่ผ่าน / no port | double-tap RESET → เลือกพอร์ตใหม่ → upload อีกครั้ง |
| Serial เป็นตัวอักษรมั่ว | baud ไม่ตรง — ตั้ง 115200 |
| แอป Android ไม่เจอเซนเซอร์ | เปิด Bluetooth **และ Location** ของมือถือ |
| iPhone ปุ่มเชื่อมเทา/ไม่ขึ้น | Safari ใช้ไม่ได้ → เปิดผ่านแอป Bluefy |
| นับ rep พลาด | จูน `HIGH_G`/`LOW_G`/`MIN_REP_MS` (ดูขั้นที่ 3) |

---

## 📏 ความแม่นที่คาดหวังได้ (ตามตรง)
- **นับ rep:** แม่นดีมากบนท่าคอมพาวด์ (งานวิจัย <6% error)
- **velocity:** อุปกรณ์ DIY แบบอินทิเกรตล้วนคลาดเคลื่อนได้เยอะ (งานวิจัย DIY ~12% หรือมากกว่า)
  → ใช้ดู "แนวโน้ม" (เร็ว/ช้าลง) ได้ดี, ค่าตัวเลขเป๊ะๆ อย่าเพิ่งเชื่อ 100%
- ของเชิงพาณิชย์ (GymAware ฯลฯ) แม่นกว่าเพราะใช้ encoder/laser — ของเราเน้น "นับ rep + ดูเทรนด์" พอ
